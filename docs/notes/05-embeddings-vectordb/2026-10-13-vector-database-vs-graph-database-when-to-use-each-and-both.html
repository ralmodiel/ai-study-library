Vector Database vs. Graph Database: When to Use Each (and Both for RAG)

Summary

This short reel compares vector databases and graph databases. Vector databases store embeddings, so they can find content with similar meaning. Graph databases store nodes and the relationships between them, so they can follow connections. The creator's advice: use vector search for semantic search and content-based recommendations, use a graph for relationship queries, and combine the two when building RAG.

Key points

  • Choose a database by what you need to find: things with similar meaning (vector) or connections (graph).
  • Vector databases store embeddings, which are lists of numbers that represent what a piece of data means.
  • Example: searching 'How do I get my money back?' can return the refund policy even though the wording is different. That's semantic search.
  • Vector databases fit semantic search and recommendations based on similar content.
  • Graph databases store data as nodes and the relationships between them. They answer questions like 'Who works at this company? Who do they know? How are they connected to me?'
  • Use a graph database when you need to follow relationships across people, accounts or transactions.
  • For RAG you can use both: vector search finds relevant content, and a graph follows the connections between those pieces.

Try this

  • Before picking a database, decide whether you need similarity search (vector) or relationship traversal (graph).
  • When building RAG, think about combining vector search for retrieval with a graph for following connections.
  • Build a RAG system that uses vector search to retrieve relevant content and a graph database to follow the relationships between the retrieved items.
