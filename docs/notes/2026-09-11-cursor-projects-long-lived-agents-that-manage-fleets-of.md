# Cursor Projects: Long-Lived Agents That Manage Fleets of Coding Agents

Melvin Vivas · X video post · 2026-09-11 · 1:33 · 678 views · [Open on X](https://x.com/melvindvivas/status/2098411199478296673)

**Topics:** AI Dev Tools & Productivity, AI Agents, Tool Use & MCP · **Level:** intermediate

## Summary

Melvin Vivas shares Cursor's launch video for Projects, a new kind of agent in Cursor. A Project agent runs on its own computer, works with you over months, and manages fleets of sub-agents for you. You talk to it in one ongoing chat instead of managing many threads. It learns your habits, reacts to events like Slack messages, GitHub PRs and cron jobs, and Cursor says it can run thousands of agents in parallel.

## Key points

- Projects is a new Cursor agent type. It manages fleets of agents for you, works with you for months, and runs on its own dedicated computer.
- You work in one persistent chat per project. The Project agent coordinates the work that used to be spread across many separate agent threads.
- The pitch is a move away from micromanaging each agent, turn by turn, toward working with a more autonomous, human-like colleague.
- It remembers what you've asked for before. For example, once a PR is opened it automatically runs follow-up steps like code simplification and other skills you've requested in the past.
- It can trigger on events: Slack messages, GitHub PRs, and scheduled cron jobs.
- There's no onboarding or setup wizard. You set things up in normal chat, and it scales.
- A Cursor team member says some of their projects run thousands of agents. The tweet claims up to 1,000 agents can work in parallel.
- Cursor's internal numbers (from Cursor, not independently checked): Projects users merge about 6x more PRs per week, and merge rates rise about 30% in the first week.
