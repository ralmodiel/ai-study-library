Summary

A skit comparing "wannabe" and production-level AI engineering habits. Basic RAG (chunk, embed, store, retrieve) is set against production RAG, which adds hybrid search, re-ranking, query rewriting and retrieval measurement. Agents should have tightly scoped tools and controlled state (for example with LangGraph) instead of being an open-ended LLM loop. The video also says the real job is supplying the right context, the right data and reliable evaluation, not mastering prompt engineering. It ends with a pitch for the creator's paid Skool community.

Key points

  • Basic RAG means chunking documents, embedding them, storing them in a vector DB and retrieving. That is a demo, not a product.
  • Production RAG uses hybrid search (keyword plus vector) with a re-ranking step.
  • Rewrite or transform the user's query before it hits the index.
  • Measure retrieval quality before trusting any generated answer.
  • An unconstrained 'LLM in a loop with tools' wastes tokens and behaves unpredictably. Scope the tools tightly.
  • Control agent state explicitly (e.g., with LangGraph) so you know exactly what the agent is doing.
  • The creator argues prompt engineering is not the core skill. The job is giving the model the right context and data, plus reliable evaluation.

Try this

  • Upgrade basic RAG with hybrid search and re-ranking.
  • Add a query-rewriting step before retrieval.
  • Set up retrieval-quality evaluation before trusting answers.
  • Scope agent tools tightly and manage agent state explicitly (e.g., with LangGraph).
  • Focus on context, data and evaluation rather than prompt engineering alone.
  • Turn a basic RAG demo into a production-style pipeline: hybrid search, re-ranking, query rewriting and retrieval evals.
  • Rebuild a free-running tool-calling agent as a LangGraph workflow with scoped tools and explicit state.
