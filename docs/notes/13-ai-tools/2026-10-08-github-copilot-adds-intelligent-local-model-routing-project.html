GitHub Copilot Adds Intelligent Local Model Routing (Project HydraFusion)

Summary

This announcement video explains that GitHub Copilot will soon send some tasks to local models on capable machines, building on Project HydraFusion, its system for routing work across many cloud models. Copilot will find models you installed with Ollama or Microsoft Foundry Local, and it will offer MAI Code 1.1 Flash as a local model. In auto-routing mode it uses these local models for simple, long-running or offline work, so those tasks use no AI credits.

Key points

  • Project HydraFusion routes planning, implementation and execution across many cloud models. Microsoft says this gives frontier-level performance and cuts cost by up to 67%.
  • Copilot will automatically find local models installed with supported providers (Microsoft Foundry Local, Ollama), and they will appear in the model picker. You won't need to set them up inside Copilot.
  • On capable devices you can install MAI Code 1.1 Flash, a local coding model, directly from GitHub Copilot.
  • In auto-routing mode, Copilot sends simple tasks to a local model, such as explaining how a codebase works or how to run a project.
  • A suggested pattern is to plan with a large frontier model (e.g. Astra), then hand the implementation to a local model that can run overnight.
  • Copilot automations (scheduled background tasks) suit local models well: they can run very long tasks and use zero AI credits.
  • Local models keep working offline, so you can still code with AI when you have no internet connection.
  • Project HydraFusion is available now under Experimental Settings in GitHub Copilot. Local routing is coming soon.
