# Cursor 3: An Agent-First IDE for Local and Cloud Coding Agents

Melvin Vivas · X video post · 2026-04-02 · 1:30 · 78 views · [Open on X](https://x.com/melvindvivas/status/2039789235100930287)

**Topics:** AI Dev Tools & Productivity, AI Agents, Tool Use & MCP, Industry Trends & Job Market · **Level:** beginner

## Summary

Melvin Vivas reshares Cursor's launch video for Cursor 3, which rebuilds the editor around coding agents. You talk to agents to build software. They can run locally or in the cloud, and you can still use full IDE features like language servers, go-to-definition and remote SSH. The video presents Cursor's approach as three parts that work together: a model (Composer 2), a product (Cursor 3) and a runtime (cloud agents with sandboxes).

## Key points

- Cursor 3 is pitched as 'a home for your agents', built for a world where agents write most of the code, but it keeps the depth of a professional dev environment (language servers, files, remote SSH).
- You can run as many agents as you want, either quickly on your own computer or by handing off whole projects to agents running in the cloud.
- Workflow: talk to agents, review their changes in one place, test them, and take them all the way to a merged PR. You can still dive in by clicking around and using go-to-definition.
- Moving between local and cloud is seamless: pull a cloud agent down to your machine, iterate with it, then send it back to the cloud to keep working on its own.
- Cloud agents (announced about a month earlier) run code end to end in their own sandbox and can work on full projects.
- Composer 2 (announced a couple of weeks earlier) is Cursor's own frontier coding model, described as having very high usage limits and fast speeds.
- Cursor's stated goal: combine model, product and runtime so agents feel like colleagues, with the developer orchestrating many agents across different machines.
