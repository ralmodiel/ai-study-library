Use a Hugging Face Inference Endpoint as a Custom Model Provider in Pi Agent

This note summarises a post by Melvin Vivas on X, posted 6 October 2026. The original belongs to Melvin Vivas.

Summary

Shows how to host an open model (a GGUF build of Qwen3.8-27B) on Hugging Face Inference Endpoints and add it to the Pi coding agent as a provider. The endpoint offers an OpenAI-compatible API. You point Pi's models.json at the endpoint's /v1 URL, then the hosted model works like any other provider.

Key points

  • Deploy an open model on Hugging Face Inference Endpoints (endpoints.huggingface.co); the model used here is Qwen3.8-27B-UD-Q4_K_M.
  • In Pi's models.json, add a 'huggingface' provider with baseUrl https://<instance-id>.endpoints.huggingface.cloud/v1 and api 'openai-completions'.
  • Read the API key from an environment variable: apiKey '$HF_ENDPOINT_API_KEY'.
  • Compatibility flags: supportsDeveloperRole false, supportsReasoningEffort false, maxTokensField 'max_tokens'.
  • Model entry: id 'unsloth/Qwen3.8-27B-GGUF', reasoning false, text input, contextWindow 32768, maxTokens 16384.
  • Replace <instance-id> with your endpoint ID and set HF_ENDPOINT_API_KEY before running Pi.

  • Deploy an open model on Hugging Face Inference Endpoints.
  • Add the provider block to Pi's models.json, replacing <instance-id> with your endpoint ID.
  • Set the HF_ENDPOINT_API_KEY environment variable.
