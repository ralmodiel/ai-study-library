Keep agent orchestration on the model its harness was tuned for

This note summarises a post by Melvin Vivas on X, posted 8 October 2026. The original belongs to Melvin Vivas.

Summary

The creator explains that Grok Bot's agent harness is tuned to Grok 4.7, so switching the orchestrator to another model such as Opus 5.5 could make orchestration worse. He suggests keeping Grok 4.7 as the orchestrator, sending specialized work to a mix of Grok and Opus, and letting advanced users choose models instead of relying only on a smart router.

Key points

  • Agent harnesses are often tuned to one model, so swapping the orchestrator model can hurt performance
  • Keep the orchestrator on the model the harness was tuned for (Grok 4.7 here)
  • Send specialized subtasks to a mix of models (Grok and Opus)
  • A smart model router is a good default
  • Advanced users should still be able to pick models manually
